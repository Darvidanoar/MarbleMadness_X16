# Marble Madness for the Commander X16

This port runs the original NES game code on the Commander X16. The 6502 code from
all four PRG banks is relocated into X16 memory and runs natively on the 65C02.
A small runtime emulates the NES hardware the game talks to (PPU, APU, controllers,
mapper) using VERA, the VERA PSG and the KERNAL joystick API.

## Building

To assemble the sources in this directory you only need cc65 (`ca65`/`ld65`) and
`make`; nothing outside this directory is used:

```sh
make                    # assemble and link MARBLE.PRG
make X16_DEFS="..."     # same, with extra assembler options (run `make clean` first)
make clean              # remove obj/ and MARBLE.PRG
```

`bank0.s`-`bank3.s` are the game code converted for the X16. 
`runtime.s` is the hand-written X16 side. 

The build produces two files, which must be kept in the same directory:

* `MARBLE.PRG`: the program (about 34KB, loads at `$0801`)
* `MMDATA.BIN`: the NES PRG banks, loaded at start-up into banked RAM (256KB)

The ROM image is not included. `MMDATA.BIN` is generated from it at build time.

## Running

On the emulator:

```sh
x16emu -prg MARBLE.PRG -run          # run from the directory holding MMDATA.BIN
```

On real hardware, copy both files to the SD card and `LOAD "MARBLE.PRG"` then `RUN`.
512KB of banked RAM is needed (RAM banks 1-33 are used).

## Controls

The game starts directly on the title screen: the NES start-up splash (PRESS START /
LICENSED BY NINTENDO) is skipped. The port is single player only: the title screen has
no player-count menu (just PRESS START) and Select does nothing there. Use the mouse (below), the keyboard (the KERNAL keyboard joystick)
or an SNES controller in port 1.

Press Esc on the title screen (shown as ESC TO EXIT under PRESS START) to quit to BASIC.
The port puts back the screen, palette, interrupt handler and zero page as they were
before the game started. RUN STOP (and Ctrl+C) work as well, because they send the same
code as Esc on X16 keymaps.

| NES      | Keyboard              | SNES pad |
|----------|-----------------------|----------|
| D-pad    | cursor keys           | D-pad    |
| A        | X or Left Ctrl (also S) | A or X |
| B        | Z or Left Alt (also A)  | B or Y |
| Start    | Enter                 | Start    |
| Select   | Left Shift            | Select   |

### Mouse

The mouse steers the marble, like the Amiga version: moving the mouse pushes
the marble in that direction (on screen), and the faster you move it, the harder
it pushes. The left button is A (jump, where the game allows it) and the right button is B.
The keyboard and joystick still work alongside it, and Start still comes from Enter or the pad.

On the name-entry screen the mouse moves the marble cursor freely over the letters,
and the left button picks the letter nearest to it (the marble snaps onto it). The
d-pad still works there too: it snaps a marble left between letters onto the nearest
one before moving it.

Because of this, the NES control-type screen (A = 90°, B = 45°) after name entry is
skipped. The d-pad always uses type A (90°: up on the pad rolls the marble up the screen).

Mouse support needs KERNAL ROM R47 or later. In x16emu, click in the window or press
Ctrl+M to capture the mouse (or start it with `-capture`).

`MOUSE_MAX` in `runtime.s` caps the push per frame (the d-pad gives 9). Raise it
to make the mouse able to push harder.

### Top speed

The marble rolls a little faster than on the NES. The NES caps its speed on the
ground at $0100 per axis, and the port allows $0130. Set `SPEED_EXTRA` in
`x16port.inc` to change this: 0 gives the NES speed, and the maximum is $7F, which
matches the cap the NES already uses for falling. You can also set it for one build
with `X16_DEFS="-D SPEED_EXTRA=0" ./build.sh`.

## How it works

| NES | X16 |
|-----|-----|
| PRG code ($8000-$FFFF, 4 banks) | Relocated into low RAM (`bank0.s`-`bank3.s`, generated by `tools/emit_x16.py`) |
| PRG data | Read from the original bank images in banked RAM. Each NES bank occupies 8 RAM banks: 8KB windows at a 4KB stride, so any `table,X/Y` or `(ptr),Y` access stays inside one window |
| Work RAM $0200-$07FF | `$9900-$9EFF` (the X16 needs `$0200-$03FF` for the KERNAL) |
| Zero page | Same addresses, except `$00`/`$01` (X16 bank registers), which move to `nes_mapper`/`nes_ppuctrl` |
| NMI | VERA VSYNC interrupt (via the KERNAL's `$0314` vector) |
| Nametables (one-screen) | VERA layer 1: 32x64 tile maps. Rows 30-59 repeat rows 0-29, so vertical scrolling wraps at 240 lines like the NES |
| Attribute tables | Palette offsets in the tile map entries |
| CHR-RAM | Converted on the fly to 2bpp tiles (background) and 4bpp tiles (sprites) |
| OAM DMA | Converted to VERA sprite attributes at the next VSYNC |
| Palette | VERA palette, NES colours translated to 12-bit RGB |
| Sprite-0 split | The game blanks the screen below the playfield with sprite 0. The port ends the display there using VERA `DC_VSTOP` |
| Mid-scanline pattern-table switch (message box) | Tile index bit 8 on the tiles inside the box |
| APU square/triangle/noise | VERA PSG voices 0-3 (frequency, volume, duty, length counters, envelopes, sweep) |
| Controllers | KERNAL `joystick_scan`/`joystick_get` |
| (mouse, not on the NES) | Raw PS/2 packets (`ps2data_raw`), added as acceleration at bank 0 `$C1AF`, and moving the name-entry cursor at `$90D2` |

## Debug builds

`build.sh` passes `$X16_DEFS` to the runtime assembler:

* `-D DEBUG_INPUT`: replay a controller script from `debug_input.inc` (made by `tools/mkinput.py`)
* `-D DEBUG_DUMP_FRAME=n`: dump the machine (`x16emu -dump RBV`) and exit before game frame *n*
* `-D DEBUG_TRACE_FRAME=n`: call `dbg_trace_start` at game frame *n* (use `x16emu -trace <addr>`)
* `-D DEBUG_MOUSE_FRAME=n -D DEBUG_MOUSE_DX=x -D DEBUG_MOUSE_DY=y`: fake mouse movement of
  (x, y) per frame from game frame *n*
* `-D DEBUG_MOUSE_PACKET -D DEBUG_MOUSE_P0=a -D DEBUG_MOUSE_P1=b -D DEBUG_MOUSE_P2=c`: feed this raw
  PS/2 packet every VSYNC instead of the real mouse
* `-D DEBUG_POKE_FRAME=n -D DEBUG_POKE_ADDR=a -D DEBUG_POKE_VAL=v`: poke a value before frame *n*
* `-D SPEED_EXTRA=0`: NES top speed (needed for lockstep once the marble reaches top speed)
* `-D DEBUG_RACE=r`: start on course *r* (0-5) instead of the Practice race, with player 1
  kept in the game as if the earlier races were won (`lockstep.py ... race=r` does the same)

`tools/lockstep.py` runs the same input script on a reference NES emulator
(`tools/nesref.py`) and compares the game's RAM with an X16 dump at the same game
frame. `tools/viscmp.py` renders the dumped VERA state next to the NES picture.
This is how the port was checked against the original. With scripted input
through the title, the menus, name entry and a race on each of the six courses,
the game's RAM matched the NES exactly at every checked frame. The only
difference was the music tempo counter, which drifts by a tick because loading
screens take a different number of frames.

## Known limitations

* The position of the second message band (message 4, after finishing a race) is
  estimated from the game's delay loops rather than measured.
* Sound is an approximation of the NES APU on the VERA PSG; the DMC channel is
  not used by the game and is not emulated.
* The NES frame is not pre-empted by the next vblank as on a real NES. Frames
  always run to completion, which only matters if the game falls behind.
